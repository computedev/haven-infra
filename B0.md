# B0 — The `count` trap

What does `terraform plan` show when a middle landlord account is removed from the list? Why is
that dangerous here? What's the fix?

<!-- Your answer here -->

### problem 
- statefile stores the resource in aws_s3_bucket.landlord_media[1] this format.
- Once the middle value is removed it look it as changes and tries to do force replacement
- this will indeed create new bucket and delete the old one 
    ```text
          ~ bucket                      = "haven-media-la-003" -> "haven-media-la-004" # forces replacement
    ```

### solution

- for_each looping to ensure that the values are used to store the terrform.state not numercial using count
- moved block to ensure the changes are propely migrated to a new block defined.
